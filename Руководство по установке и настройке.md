# FileServer: Руководство по установке и настройке (HTTP и HTTPS)

Это подробное руководство описывает процесс сборки, настройки и запуска сервера `FileServer` как в обычном режиме (HTTP), так и в защищённом режиме (HTTPS с использованием TLS-сертификата).

---

## 1. Системные требования

Перед началом работы убедитесь, что на сервере установлено:
*   **Java Development Kit (JDK) 21** или выше (`java -version`).
*   **Apache Maven 3.8+** (`mvn -version`).
*   Открытые порты:
    *   **8080** — основной порт веб-интерфейса и API.
    *   **8081** — порт сигналинга для видеотрансляций (WebRTC).

---

## 2. Сборка проекта

1. Откройте терминал в корневой папке проекта (где находится `pom.xml`).
2. Выполните сборку:
   ```bash
   mvn clean package
   ```
3. После успешной сборки в папке `target/` появится исполняемый JAR-файл, например `file-server-1.0-SNAPSHOT.jar`.

---

## 3. Структура конфигурации (`config.json`)

Вся настройка сервера осуществляется через файл `config.json`, который должен лежать в директории запуска сервера.
Сервер поддерживает **комментарии** (символы `#` и `//`), которые вырезаются парсером перед чтением JSON.

### 3.1. Базовый `config.json` (Режим HTTP)
По умолчанию сервер работает без шифрования. Если блок `"https"` отсутствует или `"enabled": false`, сервер запустится по HTTP.

```json
{
  "http": {
    "port": 8080,
    "host": "0.0.0.0"
  },
  "web": "www",
  "users": [
    {
      "name": "admin",
      "password": "StrongPassword",
      "quota": -1,
      "console": true
    }
  ],
  "shares": [
    {
      "name": "",
      "physical": "/opt/filebd/data",
      "type": "folder",
      "access": ["read", "write", "delete"],
      "anonymous": false,
      "users": ["admin"]
    }
  ]
}
```

## 4. Настройка HTTPS (TLS)

Для работы по HTTPS вам понадобятся два файла:
1.  **Сертификат** (`.crt` или `.pem`) — публичная часть.
2.  **Приватный ключ** (`.key`) — секретная часть (никому не показывать).

### 4.1. Генерация самоподписанного сертификата
Вы можете использовать следующую команду OpenSSL (замените `smwrap.ru` и IP на свои):

```bash
sudo mkdir -p /opt/prosody/config/certs/
sudo openssl req -x509 -newkey rsa:4096 -nodes \
  -keyout /opt/prosody/config/certs/smwrap.ru.key \
  -out /opt/prosody/config/certs/smwrap.ru.crt \
  -days 3650 \
  -subj "/CN=www.smwrap.ru" \
  -addext "subjectAltName=DNS:smwrap.ru,DNS:www.smwrap.ru,DNS:conference.smwrap.ru,DNS:upload.smwrap.ru,IP:109.203.192.122,IP:192.168.15.32" \
  -addext "basicConstraints=critical,CA:TRUE" \
  -addext "keyUsage=critical,digitalSignature,keyEncipherment,keyCertSign"

sudo chown -R 1000:1000 /opt/prosody/config/certs
```

### 4.2. Включение HTTPS в `config.json`
Добавьте блок `"https"` в ваш `config.json`. Укажите абсолютные пути к сертификату и ключу.

```json
{
  "http": {
    "port": 8080,
    "host": "0.0.0.0"
  },

  "https": {
    "enabled": true,
    "cert": "/opt/prosody/config/certs/smwrap.ru.crt",
    "key": "/opt/prosody/config/certs/smwrap.ru.key"
  },

  "web": "www",
  // ... остальные настройки ...
}
```

*Примечание:* Порт остаётся тем же (`8080`). Вы будете обращаться к серверу по адресу `https://www.smwrap.ru:8080/`.

## 5. Запуск сервера

В зависимости от того, как собран JAR (например, `file-server-1.0-SNAPSHOT.jar`):

```bash
# Запуск с указанием конфига
java -jar target/file-server-1.0-SNAPSHOT.jar --config config.json

# Либо, если JAR собран с зависимостями (Shade plugin)
java -jar target/file-server-1.0-SNAPSHOT.jar
```

При успешном запуске в консоли появится:
```text
[FileServer] HTTPS mode enabled
[FileServer] started
  listen   : https://0.0.0.0:8080
  web root : /opt/filebd/www
  users    : [admin]
  shares   : 1
```

## 6. Настройка WebRTC (Видеотрансляции)

Если вы включили HTTPS, **критически важно**, чтобы WebSocket для видеотрансляций также работал по защищённому протоколу (`wss://`), иначе браузер заблокирует соединение как «Mixed Content» (смешанный контент).

1.  В `config.json` включите `videochat`:
    ```json
    "videochat": {
      "enabled": true,
      "port": 8081,
      "wsGuid": "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"
    }
    ```
2.  Убедитесь, что порт **8081** открыт в фаерволе.
3.  **Важно:** Для работы `wss://` (защищённого WebSocket) на порту 8081 сервер `VideoChatServer.java` должен использовать `SSLContext`, созданный из того же сертификата, что и основной HTTP-сервер. (Код сервера должен быть модифицирован для создания `SSLServerSocket` вместо обычного `ServerSocket`).
4.  Клиентский JavaScript (и плагин) автоматически определят протокол: если страница открыта по `https://`, они будут использовать `wss://`.

## 7. Устранение неполадок (Troubleshooting)

### 7.1. Браузер пишет «Ваше соединение не защищено» (NET::ERR_CERT_AUTHORITY_INVALID)
Это нормально для **самоподписанных** сертификатов.
*   Нажмите **«Дополнительно»**.
*   Нажмите **«Перейти на сайт (небезопасно)»**.
*   Браузер запомнит исключение для вашего домена.

### 7.2. Ошибка `403 Forbidden` при запросах
Убедитесь, что в `config.json` в блоке `"shares"` для нужной папки указан ваш пользователь в массиве `"users"`, либо включён режим `"anonymous": true`.

### 7.3. Не запускается HTTPS (Ошибка парсинга ключа)
Java чувствительна к формату ключей. Убедитесь, что:
*   Приватный ключ начинается с `-----BEGIN PRIVATE KEY-----` (PKCS#8). Если начинается с `-----BEGIN RSA PRIVATE KEY-----`, конвертируйте его:
    ```bash
    openssl pkcs8 -topk8 -inform PEM -outform PEM -in smwrap.ru.key -out smwrap.ru_pkcs8.key -nocrypt
    ```
*   Сертификат начинается с `-----BEGIN CERTIFICATE-----`.
*   Пути в `config.json` указаны абсолютные и не содержат опечаток.

### 7.4. Видеотрансляция не работает
*   Если вы работаете по **HTTPS**, а трансляция не идёт — проверьте консоль браузера (F12). Если там ошибка `WebSocket connection to 'ws://...' failed`, значит клиентский код или плагин не переключился на `wss://`.
*   Если вы работаете по **HTTP**, браузер заблокирует доступ к камере. В этом случае **обязательно** используйте плагин для трансляции.

## 8. Автозапуск (Systemd)

Если вы хотите, чтобы сервер работал в фоне и запускался при перезагрузке Linux, создайте файл сервиса:

```bash
sudo nano /etc/systemd/system/file-server.service
```

Вставьте:
```ini
[Unit]
Description=FileServer (Java)
After=network.target

[Service]
Type=simple
User=filebd
WorkingDirectory=/opt/filebd
ExecStart=/usr/bin/java -jar /opt/filebd/file-server-1.0-SNAPSHOT.jar --config /opt/filebd/config.json
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Активируйте:
```bash
sudo systemctl daemon-reload
sudo systemctl enable file-server
sudo systemctl start file-server
```

Проверить логи:
```bash
sudo journalctl -u file-server -f
```
