# Обслуживание SSL-сертификата Let's Encrypt

Сертификаты, выданные Let's Encrypt, действуют **ровно 90 дней** (3 месяца). Поскольку вы используете ручной метод (DNS Challenge), сертификат **не обновляется автоматически**. За его обновлением нужно следить вручную.

---

## 1. Как узнать, сколько дней осталось до окончания работы сертификата

Самый простой и быстрый способ — использовать утилиту `openssl` прямо на сервере. Выполните в терминале:

```bash
sudo openssl x509 -enddate -noout -in /etc/letsencrypt/live/smwrap.ru/fullchain.pem
```

**Пример вывода:**
```text
notAfter=Jan 18 12:34:56 2027 GMT
```
Это покажет точную дату и время окончания действия.

**Проверка оставшихся дней:**
Если вы хотите сразу увидеть, сколько дней осталось, выполните эту команду:
```bash
echo $(( ($(date -d "$(sudo openssl x509 -enddate -noout -in /etc/letsencrypt/live/smwrap.ru/fullchain.pem | cut -d= -f2)" +%s) - $(date +%s)) / 86400 )) дней
```
*(Она выведет число, например: `89 дней`).*

Также вы можете зайти на сайт вашего домена (например, `https://www.smwrap.ru:8080/`), нажать на **замочек** в адресной строке браузера -> **«Подключение защищено»** -> **«Сертификат действителен»** и посмотреть дату там.

## 2. Инструкция по перевыпуску сертификата (MD)

Когда до окончания действия останется **10–15 дней** (или если вы случайно удалили сертификат), выполните следующие шаги. Сервер при этом можно **не останавливать**.

### Шаг 1. Запустите Certbot
Выполните команду для запроса нового сертификата:
```bash
sudo certbot certonly --manual --preferred-challenges dns -d smwrap.ru -d www.smwrap.ru
```
*(Certbot сам поймет, что старый сертификат истекает, и предложит его обновить).*

### Шаг 2. Скопируйте новые коды
Certbot выдаст вам **два новых длинных кода**:
1. Для `_acme-challenge.smwrap.ru`
2. Для `_acme-challenge.www.smwrap.ru`
   **Не закрывайте терминал и не нажимайте Enter!**

### Шаг 3. Обновите записи в Рег.ру
Зайдите в панель Рег.ру -> **Домены** -> `smwrap.ru` -> **DNS-серверы и управление зоной**.
1. Найдите существующую TXT-запись `_acme-challenge`. Нажмите на значок **редактирования (карандаш)** и замените старое значение на **первый новый код**.
2. Найдите TXT-запись `_acme-challenge.www`. Нажмите на **карандаш** и замените значение на **второй новый код**.
3. Сохраните изменения.

### Шаг 4. Подождите и завершите проверку
*   **Подождите 3–5 минут**, чтобы DNS-серверы Рег.ру обновили записи.
*   Вернитесь в терминал и нажмите **Enter**. Certbot проверит записи и сохранит новые файлы в папку `/etc/letsencrypt/live/smwrap.ru/`.

### Шаг 5. Пересоберите `keystore.p12`
Java-сервер не увидит новые файлы `.pem`, пока мы не упакуем их в бинарный `.p12` (иначе сервер продолжит использовать старый сертификат, который скоро истечет).
Выполните команду пересборки:
```bash
sudo openssl pkcs12 -export \
  -in /etc/letsencrypt/live/smwrap.ru/fullchain.pem \
  -inkey /etc/letsencrypt/live/smwrap.ru/privkey.pem \
  -out /home/myasnikovia/JavaProject/FileServer_git/certs/keystore.p12 \
  -name server \
  -passout pass:changeit
```
*(Пароль `changeit` должен совпадать с тем, что указан в вашем `config.json`).*

### Шаг 6. Перезапустите сервер
Новый сертификат готов. Чтобы сервер его подхватил, перезапустите его:
```bash
# Остановите текущий процесс (Ctrl+C или kill)
cd /home/myasnikovia/JavaProject/FileServer_git
sudo java -jar file-server.jar
```
В логах снова должно появиться `[FileServer] HTTPS mode enabled`. Проверьте замочек в браузере — дата окончания должна сдвинуться на 3 месяца вперед.

---

## 💡 Полезный лайфхак: напоминание в календарь
Так как сертификат нужно обновлять вручную, сразу после перевыпуска поставьте напоминание в календаре (Google Calendar, Яндекс.Календарь) на дату **«за 14 дней до истечения»**. Это убережет ваш сайт от внезапного появления красного экрана с ошибкой у всех пользователей.
