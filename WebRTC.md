# Руководство: Трансляция видео с веб-камеры (WebRTC)

Данное руководство описывает функционал прямой трансляции видео с веб-камеры через браузер с использованием технологии **WebRTC** и сервера сигналинга **FileServer**.

---

## 1. Архитектура и принцип работы

Система состоит из трёх компонентов:
1. **Плагин «Video Chat Broadcaster (WebRTC)»** — расширение для браузера Chrome/Edge. Захватывает видео с веб-камеры и микрофона.
2. **Сервер сигналинга (VideoChatServer)** — отдельный модуль на Java (порт `8081`). Он **не передаёт видео**, а только помогает плагину и зрителям найти друг друга (обменивается SDP-пакетами и ICE-кандидатами).
3. **Просмотрщик (FAR Web UI)** — встроенный интерфейс для зрителей. Подключается к серверу сигналинга и принимает видеопоток.

> **Важно:** Видео и звук передаются **напрямую (P2P)** от вещающего к каждому зрителю. Нагрузка на сервер минимальна, но исходящий интернет-канал должен выдерживать передачу видео на всех зрителей.

---

## 2. Системные требования

* **Сервер**:
    * Java 21+ (из-за использования виртуальных потоков).
    * Открытые порты: **`8080`** (веб-интерфейс и API) и **`8081`** (WebSocket-сигналинг).
* **Браузер (Вещатель)**: Google Chrome, Microsoft Edge или Яндекс.Браузер с установленным расширением.
* **Браузер (Зритель)**: Любой современный браузер с поддержкой WebRTC.
* **Сеть**: Для работы за NAT (через интернет) используется публичный STUN-сервер (`stun.l.google.com:19302`).

---

## 3. Настройка сервера

В файле `config.json` убедитесь, что включен модуль видеоконференций:

```json
{
  "http": {
    "port": 8080
  },
  "videochat": {
    "enabled": true,
    "port": 8081,
    "wsGuid": "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"
  }
}
```

При запуске сервера в консоли должна появиться строка:
```text
[FileServer] VideoChat started on port 8081
```

> ⚠️ **Не забудьте открыть порт 8081 в брандмауэре** (Firewall / UFW / Security Groups), иначе зрители не смогут подключиться!

---

## 4. Установка плагина (только для Вещателя)

1. Скачайте папку с плагином (файлы `manifest.json`, `background.js`, `capture.html`, `capture.js`, `bridge.js`, `popup.html`, `popup.js`).
2. Откройте браузер и перейдите по адресу:
    * Chrome: `chrome://extensions/`
    * Edge: `edge://extensions/`
    * Яндекс: `browser://extensions/`
3. Включите **«Режим разработчика»** (Developer mode) в правом верхнем углу.
4. Нажмите кнопку **«Загрузить распакованное расширение»** (Load unpacked) и выберите папку с плагином.
5. Плагин **«Video Chat Broadcaster (WebRTC) 3.0.0»** установлен.

---

## 5. Инструкция по использованию

### Шаг 1: Вещание (Запуск камеры)

1. Откройте веб-интерфейс FileServer: `http://<IP-сервера>:8080`
2. Авторизуйтесь под своим пользователем.
3. В верхней панели инструментов нажмите кнопку **🎥 Вещать**.
4. Откроется окно «Начать трансляцию». Дождитесь проверки плагина (должна загореться зеленая плашка *«Плагин обнаружен»*).
5. Введите имя комнаты (например, `main` или `office1`) и нажмите **▶ Начать трансляцию**.
6. Плагин откроет отдельное небольшое окно браузера с запросом доступа к камере. **Нажмите «Разрешить»**.
7. В окне плагина появится ваше изображение. Статус в основном окне сменится на *«🔴 Трансляция запущена в комнате...»*.

### Шаг 2: Просмотр (Зрители)

1. Зритель открывает веб-интерфейс FileServer: `http://<IP-сервера>:8080` (авторизация не обязательна, если включен анонимный доступ, но лучше авторизоваться).
2. В верхней панели нажимает кнопку **📺 Трансляция**.
3. В открывшемся окне вводит **точно такое же** имя комнаты (например, `main`) и нажимает **▶ Подключиться**.
4. Через 1-3 секунды (пока идет обмен ключами) статус сменится на *«Подключено»*, и появится видео с камеры вещателя.

### Шаг 3: Завершение

* **Вещатель** нажимает **■ Остановить** в окне лаунчера (или закрывает окно с камерой).
* **Зритель** нажимает **■ Отключиться** в окне просмотра.

## 6. Возможные проблемы и их решение

### 🔴 Зависает на статусе «Подключение к серверу...»
**Причина:** Браузер не может достучаться до порта `8081`.
**Решение:**
1. Проверьте, открыт ли порт 8081 на сервере (в облаке или локальном фаерволе).
2. Если вы заходите по HTTPS (`https://...`), то WebSocket тоже должен быть защищенным (`wss://`). В текущей реализации используется `ws://`. Для HTTPS-сайтов браузеры блокируют `ws://` (Mixed Content).
3. Если вы используете прокси (Nginx), убедитесь, что он умеет пробрасывать WebSocket-соединения.

### 🔴 Черный экран при просмотре (статус «Подключено»)
**Причина:** Установлено соединение, но медиаданные не идут.
**Решение:**
1. Проверьте, не закрылось ли окно плагина с камерой. Если оно закрыто, вещание прекращается.
2. Убедитесь, что в настройках брандмауэра разрешен исходящий UDP-трафик (WebRTC использует UDP-порты для медиа).
3. Если вещатель и зритель находятся в разных закрытых сетях (сложный NAT), может потребоваться собственный TURN-сервер (например, `coturn`).

### 🔴 В браузере нет кнопки «🎥 Вещать»
**Причина:** Функция отключена на сервере.
**Решение:** Проверьте в `config.json` параметр `"videochat": {"enabled": true}` и перезапустите сервер.

### 🔴 В консоли ошибка `NotAllowedError`
**Причина:** Пользователь заблокировал доступ к камере.
**Решение:** Нажмите на иконку замка в адресной строке, найдите «Камера» и выберите «Разрешить». Обновите страницу.
