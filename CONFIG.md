## 1. Общая структура

`config.json` — JSON-документ с пятью возможными секциями верхнего уровня:

```json
{
  "http":    { ... },
  "web":     "www",
  "console": { ... },
  "users":   [ ... ],
  "shares":  [ ... ]
}
```

| Секция | Тип | Обязательна | Назначение |
|---|---|---|---|
| `http` | object | Нет | Порт, хост |
| `web` | string | Нет | Путь к каталогу статики |
| `console` | object | Нет | Глобальные настройки терминала |
| `users` | array | Да | Учётные записи |
| `shares` | array | Да | Виртуальные ресурсы |

Если `users` или `shares` пусты — сервер запустится, но работать будет не с чем.

**Расположение файла:** рядом с местом запуска сервера. Можно указать другой путь:

```
java ... FileServer --config C:/path/to/config.json
```

## 2. Секция `http` — параметры сервера

Определяет, где и как сервер слушает подключения.

```json
{
  "http": {
    "port": 8080,
    "host": "0.0.0.0"
  }
}
```

### Поля

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `port` | number | `8080` | TCP-порт |
| `host` | string | `"0.0.0.0"` | Интерфейс прослушивания |

### Значения `host`

| Значение | Что означает |
|---|---|
| `"0.0.0.0"` | Слушать **все** сетевые интерфейсы (доступ из локальной сети) |
| `"127.0.0.1"` | Только localhost (только с той же машины) |
| `"192.168.1.10"` | Только указанный IP |
| `"localhost"` | Разрешается в loopback |

### Переопределение через CLI

Если параметр указан в CLI, он **перекрывает** значение из config:

```bash
java ... FileServer --port 9090 --host 127.0.0.1
```

### Проверка занятости порта

**Windows:**
```bat
netstat -ano | findstr :8080
```

**Linux/macOS:**
```bash
lsof -i :8080
ss -tlnp | grep 8080
```

Если порт занят — выберите другой (например, `8081`).

## 3. Секция `web` — каталог статики

Определяет каталог, из которого отдаётся статика (`index.html`, `js/`, `css/`, `modals/`, `lib/`).

```json
{
  "web": "www"
}
```

### Поля

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `web` | string | `"www"` | Путь к каталогу статики |

### Относительный или абсолютный путь

| Значение | Что означает |
|---|---|
| `"www"` | Относительно рабочего каталога запуска (`user.dir`) |
| `"./web"` | То же |
| `"C:/JavaProject/FileServer/www"` | Абсолютный путь |
| `"/var/www/filebd"` | Абсолютный путь (Linux) |

### Что попадает в статику

Сервер отдаёт любой файл из этого каталога, **кроме**:

- `.idea/`
- `.git/`
- `.gitignore`
- `config.json`

**Даже если** эти файлы лежат внутри `www/`, они не будут отданы клиенту.

### Если каталог не найден

Сервер **всё равно запустится**, но в консоли появится предупреждение, а все запросы к `/`, `/index.html`, `/js/*` будут возвращать 404.

## 4. Секция `console` — настройки терминала

Глобальные настройки для встроенной веб-консоли (доступна только пользователям с флагом `"console": true`).

```json
{
  "console": {
    "shell": "",
    "cwd": "/home/user",
    "timeoutSec": 300,
    "maxOutputBytes": 1048576
  }
}
```

### Поля

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `shell` | string | `""` | Оболочка. Пусто = авто (`bash` на Linux, `cmd.exe` на Windows) |
| `cwd` | string | `""` | Рабочий каталог при старте. Пусто = каталог запуска сервера |
| `timeoutSec` | number | `300` | Максимальное время жизни процесса (секунд) |
| `maxOutputBytes` | number | `1048576` | Лимит вывода на одну команду (1 МБ) |

### Особенности

- Если `shell` пуст, сервер запустит `bash` (Linux/macOS) или `cmd.exe` (Windows).
- `cwd` должен существовать на сервере, иначе будет использован дефолтный каталог.
- `TERM=xterm-256color` и `LANG=C.UTF-8` устанавливаются автоматически для корректной работы `mc`, `htop`, `vim` и цветов.

## 5. Секция `users` — пользователи

Массив объектов-пользователей.

```json
{
  "users": [
    { "name": "admin", "password": "admin123", "quota": -1, "console": true },
    { "name": "olga",  "password": "olga2024", "quota": 500, "console": false }
  ]
}
```

### Поля пользователя

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | string | — | Логин. **Обязателен**, уникален |
| `password` | string | `""` | Пароль в открытом виде |
| `quota` | number | `-1` | Общая квота пользователя (МБ). `-1` — без лимита |
| `console` | boolean | `false` | Доступ к веб-терминалу (`true` — разрешено) |

### Правила

1. **Уникальность:** логин должен быть уникальным. Если два пользователя имеют одно имя — второй перезапишет первого в `Map<String, User>`.
2. **Пустое имя:** пользователи с `name = ""` **игнорируются**.
3. **Пустой пароль:** пользователь входит только по логину, без пароля.
4. **Пробелы:** `name` тримится. `password` сохраняется как есть (регистрозависимо).

### Квоты

| Значение | Что означает |
|---|---|
| `-1` | Без лимита |
| `0` | Запись запрещена полностью |
| `> 0` | Лимит в мегабайтах |

Квота пользователя — **сумма по всем shares**, к которым у него есть доступ.

## 6. Секция `shares` — общие ресурсы

Каждый share — виртуальный «ресурс», который видят пользователи. Физический путь задаётся отдельно, пользователь его не видит.

```json
{
  "shares": [
    {
      "name": "Documents",
      "physical": "C:/data/docs",
      "type": "folder",
      "access": ["read", "write", "delete"],
      "anonymous": false,
      "users": ["admin", "olga"],
      "quota": 200
    }
  ]
}
```

### Поля share

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | string | — | Виртуальное имя (видно клиенту) |
| `physical` | string | — | Физический путь на диске |
| `type` | string | `"folder"` | `folder` или `file` |
| `access` | array | `["read"]` | `read`, `write`, `delete` |
| `anonymous` | boolean | `false` | Доступ без пароля |
| `users` | array | `[]` | Список логинов, которым виден share |
| `quota` | number | `-1` | Лимит записи в этот share (МБ) |

### 6.1. `name` — виртуальное имя

Это то, что видит пользователь. Правила:
- **Не может содержать `/`** — иначе сломает парсинг виртуального пути.
- Должно быть **уникальным** среди shares.
- Регистрозависимо.

### 6.2. `physical` — физический путь

Путь на диске, где реально лежат файлы.

**Windows:**
```json
{ "physical": "C:/data/docs" }
```
**Linux/macOS:**
```json
{ "physical": "/home/user/data" }
```

Путь **нормализуется**. Относительные пути разрешаются от `user.dir` (рабочий каталог Java-процесса). Рекомендуется использовать абсолютные пути.

### 6.3. `type` — тип ресурса

| Значение | Что означает |
|---|---|
| `folder` | Папка. Есть содержимое, поддерживает `list`, вложенные файлы и папки |
| `file` | Один файл. Прямой URL отдаёт именно его |

### 6.4. `access` — права

Массив из строк. Возможные значения:

| Значение | Что разрешает |
|---|---|
| `"read"` | Просмотр списка, чтение, скачивание |
| `"write"` | Создание файлов, папок, запись |
| `"delete"` | Удаление, перемещение из share |

Если `access` пуст или отсутствует → по умолчанию `["read"]`.

### 6.5. `anonymous` — доступ без пароля

| Значение | Что означает |
|---|---|
| `false` | Доступ только для явно указанных пользователей |
| `true` | Доступ **всем** (включая анонимов) с правами `access` |

Если `anonymous: true`, то `users` игнорируется.

### 6.6. `users` — кому виден share

Используется, когда `anonymous: false`. Пустой список + `anonymous: false` → **никто не видит**.

### 6.7. `quota` — лимит записи

| Значение | Что означает |
|---|---|
| `-1` | Без лимита |
| `0` | Запись запрещена |
| `> 0` | Лимит в МБ |

Квота share и квота пользователя работают независимо. Обе проверяются перед каждой записью.

## 7. Полные примеры

### 7.1. Минимум для запуска

```json
{
  "users": [
    { "name": "admin", "password": "admin", "console": true }
  ],
  "shares": [
    { "name": "root", "physical": "C:/FileBD" }
  ]
}
```

### 7.2. Несколько пользователей с разными правами (включая консоль)

```json
{
  "http": { "port": 8080, "host": "0.0.0.0" },
  "web": "www",
  "console": {
    "shell": "",
    "cwd": "/home/admin",
    "timeoutSec": 300,
    "maxOutputBytes": 1048576
  },

  "users": [
    { "name": "admin", "password": "admin123", "quota": -1, "console": true },
    { "name": "olga",  "password": "olga2024", "quota": 500, "console": false },
    { "name": "guest", "password": "",         "quota": 100, "console": false }
  ],

  "shares": [
    {
      "name": "Documents",
      "physical": "C:/data/docs",
      "type": "folder",
      "access": ["read", "write", "delete"],
      "anonymous": false,
      "users": ["admin", "olga"],
      "quota": 200
    },
    {
      "name": "Public",
      "physical": "D:/Public",
      "type": "folder",
      "access": ["read"],
      "anonymous": true,
      "users": []
    }
  ]
}
```

### 7.3. Только анонимный доступ

```json
{
  "users": [],
  "shares": [
    {
      "name": "Media",
      "physical": "E:/Media",
      "type": "folder",
      "access": ["read"],
      "anonymous": true
    }
  ]
}
```

## 8. Комбинирование параметров

### 8.1. `anonymous: true` + `access: ["read","write"]`
Любой аноним может писать в share (например, для публичной «приёмной»).

### 8.2. Квота пользователя меньше квоты share
Пользователь сможет записать не больше своего лимита, даже если share позволяет больше.

### 8.3. Пользователь видит share, но не имеет прав
Если `write` нет в `access`, попытка записи вернёт 403.

## 9. Порядок загрузки и приоритеты

### 9.1. Последовательность

```
1. Ищем config.json (или --config <path>).
2. Парсим JSON.
3. Применяем http.port, http.host.
4. Применяем web.
5. Применяем console (shell, cwd, timeout, maxOutput).
6. Загружаем users (только с непустым name).
7. Загружаем shares (только с name и physical).
8. Переопределяем port/host/web из CLI.
9. Запускаем HttpServer.
```

### 9.2. Приоритеты

| Источник | Приоритет |
|---|---|
| CLI (`--port`, `--host`, `--web`, `--config`) | Высший |
| `config.json` | Средний |
| Дефолты в коде | Низший |

## 10. Типичные ошибки

### 10.1. Пользователь не видит share
**Причина:** логин не совпадает с элементом `users` (регистрозависимо).

### 10.2. Загрузка не проходит из-за квоты
**Причина:** превышен лимит `quota` share или пользователя.
**Решение:** увеличьте `quota` или удалите старые файлы.

### 10.3. Консоль не открывается
**Причина:** у пользователя не указано `"console": true` или отсутствует `jtermios` в сборке сервера.

### 10.4. Кириллица в путях
При запуске Java добавьте `-Dfile.encoding=UTF-8` и убедитесь, что `LANG` в системе установлен в UTF-8.

## Заключение

`config.json` — единственный источник конфигурации FileServer. Все параметры можно переопределить через CLI (`--port`, `--host`, `--web`, `--config`). Ключевые принципы:

- **Пользователь** идентифицируется логином, а флаг `console` дает доступ к терминалу.
- **Share** — виртуальный ресурс, скрывающий физический путь.
- **Квоты** — на запись, раздельные для share и пользователя.
- **Anonymous** — открывает share для всех без авторизации.

При изменении конфига **нужен перезапуск сервера** — горячей перезагрузки нет.
