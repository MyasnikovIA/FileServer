## 1. Что такое `config.json`

`config.json` — **единственный** файл конфигурации FileServer. Содержит:

- сетевые параметры (`http`);
- путь к статике (`web`);
- параметры встроенного терминала (`console`);
- список пользователей (`users`);
- список общих ресурсов (`shares`).

**Формат:** JSON (UTF-8, без комментариев, без BOM).
**Расположение:** рядом с рабочим каталогом сервера. Можно указать другой путь:

```bash
java -jar FileServer.jar --config C:/path/to/config.json
```

**Перезагрузка:** горячей перезагрузки нет — после изменения файла нужен **перезапуск сервера**.

**Валидация:** ошибки JSON ломают запуск (`SyntaxError`). Ошибки полей обычно игнорируются молча (пользователь/share с пустым именем просто не загрузится), но могут привести к неработающей конфигурации. Всегда проверяйте по логам.

## 2. Полная структура файла

```json
{
  "http":    { "port": 8080, "host": "0.0.0.0" },
  "web":     "www",
  "console": { "shell": "", "cwd": "", "timeoutSec": 300, "maxOutputBytes": 1048576 },
  "users":   [ /* ... */ ],
  "shares":  [ /* ... */ ]
}
```

| Секция | Тип | Обязательна | Пустое значение |
|---|---|---|---|
| `http` | object | Нет | Берутся дефолты (`8080` / `0.0.0.0`) |
| `web` | string | Нет | `"www"` |
| `console` | object | Нет | Значения по умолчанию |
| `users` | array | **Да** | Сервер стартует, но войти некому |
| `shares` | array | **Да** | Сервер стартует, но файлов нет |

Если `users` или `shares` пусты — сервер поднимется, но **работать будет не с чем**. Это не ошибка запуска, но это ошибка конфигурации.

## 3. Секция `http` — сетевые параметры

```json
{
  "http": {
    "port": 8080,
    "host": "0.0.0.0"
  }
}
```

### 3.1. Поля

| Поле | Тип | По умолчанию | Диапазон |
|---|---|---|---|
| `port` | number | `8080` | 1–65535 |
| `host` | string | `"0.0.0.0"` | IP-адрес или `"localhost"` |

### 3.2. Семантика `host`

| Значение | Что означает |
|---|---|
| `"0.0.0.0"` | Слушать **все** интерфейсы (доступ из локальной сети и снаружи) |
| `"127.0.0.1"` | Только loopback (только с той же машины) |
| `"::"` | Слушать все IPv6-интерфейсы (включая IPv4-mapped) |
| `"::1"` | Только IPv6 loopback |
| `"192.168.1.10"` | Только указанный IP |
| `"localhost"` | Резолвится в `127.0.0.1` (или `::1`) |

### 3.3. Переопределение из CLI

CLI **всегда перекрывает** `config.json`:

```bash
java -jar FileServer.jar --port 9090 --host 127.0.0.1
```

**Приоритет:** CLI > `config.json` > дефолт в коде.

### 3.4. Диагностика занятости порта

**Windows:**
```bat
netstat -ano | findstr :8080
tasklist | findstr <PID>
```

**Linux / macOS:**
```bash
lsof -i :8080
ss -tlnp | grep 8080
```

Если порт занят — выберите другой (например, `8081`). Если `port` не указан — будет `8080`.

### 3.5. Firewall

На **Windows** при первом запуске сервер спросит разрешение брандмауэра — разрешите для частных сетей. На **Linux** — откройте порт (пример для `ufw`):

```bash
sudo ufw allow 8080/tcp
```

Для публичного доступа — проксируйте через nginx/caddy с HTTPS; сам FileServer по умолчанию HTTP (без TLS).

## 4. Секция `web` — каталог статики

```json
{ "web": "www" }
```

### 4.1. Значения

| Значение | Что означает |
|---|---|
| `"www"` | Относительно `user.dir` (рабочего каталога Java-процесса) |
| `"./web"` | То же |
| `"C:/JavaProject/FileServer/www"` | Абсолютный путь (Windows) |
| `"/var/www/filebd"` | Абсолютный путь (Linux) |

### 4.2. Что раздаётся из `web/`

Сервер отдаёт **любой** файл из этого каталога, кроме:

- `.idea/` (каталог IDE)
- `.git/` (git-метаданные)
- `.gitignore`
- `config.json` — даже если он лежит внутри `www/`

### 4.3. Структура, которую ожидает клиент

```
www/
├── index.html
├── login.html
├── js/                    ← все модули (01-config.js … 53-…)
├── css/
├── modals/
├── lib/
│   ├── Pannellum2_5_6/
│   ├── js-dos/
│   ├── js-emscripten/
│   ├── js-nes/
│   ├── js-emulator/
│   ├── PDFObject/
│   └── xterm/
└── Data/                  ← не обязательно, если share на другой диск
```

Отсутствие любого из этих файлов → 404 в консоли браузера при загрузке. Сам сервер стартует нормально.

### 4.4. Если каталог не найден

Сервер **всё равно запустится**, но:

- В логах появится `WWW directory not found: …`
- Все запросы к `/`, `/index.html`, `/js/*`, `/css/*` вернут **404**
- REST API (`/api/*`) продолжит работать

## 5. Секция `console` — терминал

Доступна только пользователям с флагом `"console": true` в `users`.

```json
{
  "console": {
    "shell": "",
    "cwd": "/home/user",
    "timeoutSec": 300,
    "maxOutputBytes": 1048576
  }
}
```

### 5.1. Поля

| Поле | Тип | По умолчанию | Диапазон / Примечание |
|---|---|---|---|
| `shell` | string | `""` | Пусто = авто (`bash`/`cmd.exe`) |
| `cwd` | string | `""` | Пусто = каталог запуска сервера |
| `timeoutSec` | number | `300` | Секунды; по истечении процесс убивается |
| `maxOutputBytes` | number | `1048576` (1 МБ) | Лимит вывода на одну команду |

### 5.2. Автовыбор оболочки

| ОС | Дефолт при `shell: ""` |
|---|---|
| Linux | `/bin/bash` (если нет — `/bin/sh`) |
| macOS | `/bin/bash` (если нет — `/bin/zsh`) |
| Windows | `cmd.exe` |

### 5.3. Переменные окружения (устанавливаются автоматически)

- `TERM=xterm-256color` — корректные цвета в `vim`, `htop`, `mc`
- `LANG=C.UTF-8` — корректная работа с UTF-8
- `LC_ALL=C.UTF-8`

### 5.4. Влияние `cwd`

Если `cwd` **не существует** на сервере — будет использован каталог запуска сервера (не ошибка). Лучше указывать существующий путь:

```json
"cwd": "/home/admin"
```

### 5.5. Пример для Windows

```json
"console": {
  "shell": "powershell.exe",
  "cwd": "C:/Users/Admin",
  "timeoutSec": 600,
  "maxOutputBytes": 4194304
}
```

## 6. Секция `users` — пользователи

```json
{
  "users": [
    { "name": "admin", "password": "admin123", "quota": -1,  "console": true  },
    { "name": "olga",  "password": "olga2024", "quota": 500, "console": false },
    { "name": "guest", "password": "",          "quota": 100, "console": false }
  ]
}
```

### 6.1. Поля

| Поле | Тип | По умолчанию | Обязательно | Примечание |
|---|---|---|---|---|
| `name` | string | — | **Да** | Уникален, непустой, тримится |
| `password` | string | `""` | Нет | Открытый текст, регистрозависим |
| `quota` | number | `-1` | Нет | МБ; `-1` = ∞, `0` = запрет |
| `console` | boolean | `false` | Нет | Доступ к `/api/console/*` |

### 6.2. Правила загрузки

1. **Уникальность:** если два пользователя имеют одно `name`, **второй перезапишет первого** в `Map<String, User>`. Дублируйте осторожно.
2. **Пустое имя:** пользователи с `name = ""` (после trim) **игнорируются**.
3. **Пробелы:** `name` обрезается по краям; `password` сохраняется как есть.
4. **Пустой пароль:** вход только по логину (без пароля) — удобно для «гостевого» доступа.
5. **`console`:** работает только если собрана нативная часть (`jtermios`). Иначе флаг игнорируется.

### 6.3. Логин и токен

- Логин идёт через `POST /api/login` (тело: `{ "user": "...", "pass": "..." }`).
- Сервер выдаёт **Bearer-токен** (срок жизни — 24 часа, либо до перезапуска).
- Токен кладётся в cookie `filebd_token` (SameSite=Lax, Path=/).
- Все дальнейшие запросы авторизуются либо через заголовок `Authorization: Bearer <token>`, либо через cookie.

## 7. Секция `shares` — общие ресурсы

```json
{
  "shares": [
    {
      "name": "Documents",
      "physical": "C:/data/docs",
      "type": "folder",
      "access": ["read", "write", "delete"],
      "anonymous": false,
      "users": ["admin", "olga"],
      "quota": 200
    }
  ]
}
```

### 7.1. Поля

| Поле | Тип | По умолчанию | Обязательно | Примечание |
|---|---|---|---|---|
| `name` | string | — | **Да** | Уникально, без `/` |
| `physical` | string | — | **Да** | Абсолютный путь рекомендуется |
| `type` | string | `"folder"` | Нет | `folder` или `file` |
| `access` | array | `["read"]` | Нет | `read` / `write` / `delete` |
| `anonymous` | boolean | `false` | Нет | Если `true` — `users` игнорируется |
| `users` | array | `[]` | Нет | Список логинов (без `anonymous`) |
| `quota` | number | `-1` | Нет | МБ; `-1` = ∞, `0` = запрет |

### 7.2. `name` — виртуальное имя

То, что видит пользователь в корне. Правила:

- **Не должно содержать `/`** — иначе парсинг виртуального пути сломается.
- **Уникально** среди всех shares (иначе второй перезапишет первый в `Map`).
- **Регистрозависимо** (`Documents` ≠ `documents`).

### 7.3. `physical` — физический путь

| Пример | ОС | Примечание |
|---|---|---|
| `C:/data/docs` | Windows | Прямые слэши — предпочтительнее |
| `D:\\Documents` | Windows | Двойные обратные слэши в JSON |
| `/home/user/data` | Linux/macOS | Абсолютный |
| `./DATA` | любая | Относительно `user.dir` |

**Важно:** путь **не обязан существовать** на момент старта. Если путь не существует:

- при попытке чтения → `404 Not Found`
- при попытке записи → `500 Internal Server Error`

Создайте каталог заранее (или вручную, или через клиент).

### 7.4. `type` — тип ресурса

| Значение | Что означает |
|---|---|
| `folder` | Папка. Поддерживает `list`, вложенные файлы и папки |
| `file` | Один файл. Прямой URL (`/shareName`) отдаёт этот файл |

**`type: "file"`** используется редко — обычно для «одиночного файла» вроде большой ISO или дистрибутива.

### 7.5. `access` — права

| Значение | Что разрешает |
|---|---|
| `"read"` | `GET /api/list`, `GET /api/stat`, скачивание, просмотр |
| `"write"` | `PUT /api/write`, `POST /api/mkdir`, `POST /api/copy`, `POST /api/move` (внутри share) |
| `"delete"` | `DELETE /api/delete`, `POST /api/move` (наружу) |

**Если `access` отсутствует или пуст** → по умолчанию `["read"]`.

**Порядок не важен** — массив превращается в `Set<String>`.

### 7.6. `anonymous` — открытый доступ

| Значение | Кому виден share |
|---|---|
| `false` | Только `users` (явный список) |
| `true` | **Всем**, включая неавторизованных |

**Правила:**
- При `anonymous: true` массив `users` **игнорируется** — доступ есть у всех.
- При `anonymous: false` и `users: []` — **никто не видит** (не ошибка, но, вероятно, не то, что нужно).

### 7.7. `quota` — лимит записи

| Значение | Что означает |
|---|---|
| `-1` | Без лимита |
| `0` | Запись **полностью запрещена** |
| `> 0` | Лимит в **мегабайтах** |

**Квота работает только на запись.** Чтение и удаление разрешены всегда (если `access` позволяет).

## 8. Квоты: как они работают

В FileServer **две независимые квоты**:

1. **Квота пользователя** (`users[].quota`)
2. **Квота share** (`shares[].quota`)

При **каждой** записи (`PUT /api/write`, `POST /api/copy`, `POST /api/move`) сервер проверяет **обе** квоты:

```
if (used_by_user + delta > user.quota)  → 507 Quota Exceeded
if (used_in_share + delta > share.quota) → 507 Quota Exceeded
```

### 8.1. Квота пользователя

Суммируется по **всем** shares, к которым пользователь имеет доступ. Если пользователь пишет в `Documents` (100 МБ) и в `Public` (200 МБ), а его `quota = 500`, у него осталось `500 - 300 = 200 МБ` суммарно.

### 8.2. Квота share

Ограничивает **весь** share независимо от того, кто пишет. Если в `Documents` (`quota = 200`) уже лежит 199 МБ, ни один пользователь не сможет записать ещё 2 МБ.

### 8.3. Комбинирование

| Пользователь | Share | Результат |
|---|---|---|
| `quota = -1` | `quota = -1` | Без лимитов |
| `quota = 100` | `quota = 500` | Не более 100 МБ |
| `quota = 500` | `quota = 100` | Не более 100 МБ |
| `quota = 0` | любая | Запись запрещена |
| любая | `quota = 0` | Запись запрещена |

### 8.4. Формат ответа 507

Сервер возвращает JSON:

```json
{
  "error": "Quota exceeded",
  "scope": "Documents",
  "quotaMb": 200,
  "usedBytes": 208666624,
  "freeBytes": 0,
  "deltaBytes": 5242880,
  "status": 507
}
```

Клиент выводит человекочитаемое сообщение вроде:

> `Quota exceeded — шары "Documents" (лимит 200 MB, занято 199.00 MB, свободно 0 B, нужно 5.00 MB)`

## 9. Права доступа: полная матрица

Для каждого share проверяются:

1. `access` содержит нужное право
2. Пользователь авторизован (или `anonymous: true`)

| Операция | Требуется `access` |
|---|---|
| `GET /api/list` | `read` |
| `GET /api/stat` | `read` |
| `GET /api/read` | `read` |
| `PUT /api/write` | `write` |
| `POST /api/mkdir` | `write` |
| `DELETE /api/delete` | `delete` |
| `POST /api/copy` (внутри) | `read` + `write` |
| `POST /api/move` (внутри) | `read` + `write` + `delete` |
| `POST /api/copy` (наружу) | `read` + `write` (в целевой share) |
| `POST /api/move` (наружу) | `read` + `write` + `delete` |

Если права нет — сервер вернёт:

| HTTP | Причина |
|---|---|
| `401` | Не авторизован |
| `403` | Авторизован, но нет нужного `access` |
| `404` | Файл/путь не найден, либо share не виден пользователю |

## 10. Безопасность: чек-лист

### 10.1. Пароли

- **Пароли хранятся в открытом виде** в `config.json`. Файл должен быть доступен только владельцу (`chmod 600 config.json` на Linux, отключите наследование прав на Windows).
- Используйте **сложные** пароли, особенно для `console: true`.
- Не коммитьте `config.json` в git (`.gitignore`).

### 10.2. `console: true`

Даёт **полноценный shell** на сервере под тем же пользователем, что и Java-процесс. Это **эквивалентно полному доступу** к серверу.

- Разрешайте только доверенным пользователям.
- Не открывайте сервер в интернет с включённой консолью без HTTPS и сильной аутентификации.
- По возможности ограничьте `console.timeoutSec` (например, `60` секунд).

### 10.3. Сетевой доступ

- Не используйте `"host": "0.0.0.0"`, если сервер не должен быть доступен извне.
- Для публичного доступа — прокси через nginx/caddy с TLS.
- Ограничьте `console` на уровне reverse-proxy (`/api/console/*` только из локальной сети).

### 10.4. `anonymous: true`

Любой пользователь может читать (или писать) в этот share. Не используйте для приватных данных.

### 10.5. Отдача статики

`config.json` **не отдаётся** даже если лежит в `www/`. Всё остальное — отдаётся. Не кладите приватные данные в `web/`.

## 11. Порядок загрузки и приоритеты

### 11.1. Последовательность

```
1. Ищем config.json (или путь из --config).
2. Парсим JSON (ошибка → выход с сообщением).
3. Применяем http.port, http.host (иначе дефолты).
4. Применяем web (иначе "www").
5. Применяем console (иначе дефолты).
6. Загружаем users (пропускаем пустые name).
7. Загружаем shares (пропускаем без name/physical).
8. Переопределяем port/host/web из CLI.
9. Стартуем HTTP-сервер.
```

### 11.2. Приоритеты

| Источник | Приоритет |
|---|---|
| CLI (`--port`, `--host`, `--web`, `--config`) | **Высший** |
| `config.json` | Средний |
| Дефолты в коде | Низший |

### 11.3. Что **не** переопределяется из CLI

- `users`, `shares`, `console` — только через `config.json`.

## 12. Полные примеры конфигураций

### 12.1. Минимум для запуска

```json
{
  "users": [
    { "name": "admin", "password": "admin", "console": true }
  ],
  "shares": [
    { "name": "root", "physical": "C:/FileBD" }
  ]
}
```

Что получится:
- `admin/admin` → полный доступ ко всему в `C:/FileBD`.
- Консоль доступна.
- Порт `8080`, host `0.0.0.0`.
- Без квот.

### 12.2. Локальная разработка (безопасно)

```json
{
  "http": { "port": 8080, "host": "127.0.0.1" },
  "web": "www",
  "console": {
    "shell": "",
    "cwd": "",
    "timeoutSec": 300,
    "maxOutputBytes": 1048576
  },
  "users": [
```

## 13. Типичные ошибки и их решения

### 13.1. Пользователь не видит share

**Симптом:** после логина корень пуст, в консоли `404` на `list`.

**Причины и решения:**

| Причина | Решение |
|---|---|
| `users` у share содержит другой логин | Проверьте **регистр** — `admin` ≠ `Admin` |
| `anonymous: false` и `users: []` | Добавьте логин в `users` или поставьте `anonymous: true` |
| `physical` указывает на несуществующий путь | Создайте каталог на диске |
| Опечатка в `name` | Убедитесь, что `name` совпадает с тем, что в `list` |
| Перезапуск забыт | После правки `config.json` перезапустите сервер |

### 13.2. Загрузка не проходит из-за квоты

**Симптом:** `507 Quota Exceeded`, файл на диске **не появляется** (атомарная запись).

**Решение:**
1. Проверьте `quota` пользователя и share.
2. Удалите ненужные файлы из share.
3. Увеличьте `quota` (или `-1` для отключения).

**Важно:** `507` возвращается **до** создания файла на диске — «пустых заглушек» не остаётся.

### 13.3. Консоль не открывается

**Симптом:** `/api/console/events` → 403, либо UI не показывает кнопку Console.

**Причины:**
- У пользователя нет `"console": true`.
- В сборке отсутствует нативная часть (`jtermios` — терминал не работает на некоторых ОС).
- Клиент не перезагрузил `info` — `console: true` приходит в `/api/info` только после нового логина.

**Решение:** выставить `"console": true`, перезапустить сервер, перелогиниться в клиенте.

### 13.4. Кириллица в путях «ломается»

**Симптом:** файл `Привет.txt` превращается в `????.txt`, или 404 на существующий файл.

**Причины:**
- Java запущена без `-Dfile.encoding=UTF-8`.
- `LANG` в системе не UTF-8.

**Решение:**

```bash
# Linux
export LANG=C.UTF-8
java -Dfile.encoding=UTF-8 -jar FileServer.jar
```

```bat
REM Windows
chcp 65001
java -Dfile.encoding=UTF-8 -jar FileServer.jar
```

### 13.5. `host: "localhost"` не работает из сети

**Симптом:** с другой машины `Connection refused`.

**Причина:** `localhost` резолвится в `127.0.0.1` — сервер слушает только loopback.

**Решение:** замените на `"0.0.0.0"` (все интерфейсы) или конкретный IP.

### 13.6. Два пользователя с одним именем — второй «вытесняет» первого

**Симптом:** логин одного из пользователей не работает / выдаёт права другого.

**Причина:** `Map.put(name, user)` при дубликате перезаписывает запись.

**Решение:** проверьте `users` на дубликаты `name`.

### 13.7. Два share с одним именем

**Симптом:** один из share недоступен.

**Причина:** `Map.put(name, share)` перезаписывает.

**Решение:** сделайте имена уникальными.

### 13.8. `access: []` — «ничего не работает»

**Симптом:** даже список файлов не приходит.

**Причина:** сервер заменяет пустой `access` на `["read"]`. Значит, `write`/`delete` точно не работают.

**Решение:** явно перечислите нужные права.

### 13.9. `physical` с обратными слэшами

**Симптом:** `physical` «не находится».

**Причина:** в JSON обратный слэш — escape-символ. `"C:\\path"` валиден, `"C:\path"` — нет.

**Решение:** используйте прямые слэши: `"C:/path"` — работает и на Windows.

### 13.10. Файлы пишутся в «неожиданный» каталог

**Причина:** `physical` был относительным (`./DATA`), а `user.dir` при запуске из IDE/службы оказался другим.

**Решение:** используйте **абсолютные** пути в `physical`.

## 14. Миграция и обновление

### 14.1. Обновление со старой версии FileBD

Если раньше share назывались по-другому — обновите `name` и/или создайте симлинк:

```bash
# Linux
ln -s /old/path /new/path
```

```bat
REM Windows
mklink /D C:\new\path C:\old\path
```

Тогда клиент увидит старое имя в новом `shares[]`, а данные останутся на месте.

### 14.2. Переименование share

1. Остановить сервер.
2. Переименовать в `config.json`.
3. Запустить сервер.
4. Клиенты увидят новое имя в корне. Ссылки вида `http://host:8080/OldShare/...` перестанут работать.

### 14.3. Добавление нового пользователя

1. Добавить в `users`.
2. Перезапустить сервер.
3. Пользователь логинится с новыми кредами.

### 14.4. Удаление пользователя

1. Удалить из `users`.
2. Удалить из `shares[].users`, если он там есть.
3. Перезапустить сервер.

Активные сессии (Bearer-токены) продолжат работать до истечения 24 часов или до перезапуска.

### 14.5. Изменение `physical`

1. Остановить сервер.
2. Изменить `physical`.
3. Запустить.

**Внимание:** если старый путь уже использовался, старые файлы останутся там, куда указывал старый `physical`. Их нужно скопировать вручную, если это тот же share.

## 15. Диагностика: как проверить конфиг

### 15.1. Проверить JSON

```bash
# Linux/macOS
python3 -m json.tool config.json > /dev/null && echo OK
# или
jq . config.json > /dev/null && echo OK
```

```bat
REM Windows (PowerShell)
Get-Content config.json -Raw | ConvertFrom-Json | Out-Null; "OK"
```

### 15.2. Проверить, что сервер стартовал с нужным портом

```bash
curl -s http://localhost:8080/api/info
```

Ожидаемый ответ — JSON с `username`, `shares`, `console`.

### 15.3. Проверить, что пользователь видит нужный share

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"user":"admin","pass":"admin"}' | jq -r .token)

curl -s "http://localhost:8080/api/list?path=" \
  -H "Authorization: Bearer $TOKEN" | jq .entries
```

Должен вернуть список shares, к которым у `admin` есть доступ.

### 15.4. Проверить квоту

```bash
curl -s "http://localhost:8080/api/info" \
  -H "Authorization: Bearer $TOKEN" | jq '{quota: .userQuotaMb, used: .userUsedBytes}'
```

### 15.5. Логи сервера

Обычно пишутся в `stdout`. Ищите строки:

- `Loaded config from …` — где реально взят `config.json`
- `Warning: user "" ignored` — пропущенные пользователи
- `Warning: share without physical …` — пропущенные shares
- `WWW directory not found: …` — каталог статики не найден
- `Could not bind to port …` — порт занят

### 15.6. Тест полного цикла

```bash
# 1) логин
TOKEN=$(curl -s -X POST http://localhost:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"user":"admin","pass":"admin"}' | jq -r .token)

# 2) загрузка файла
curl -X PUT "http://localhost:8080/api/write?path=test.txt" \
  -H "Authorization: Bearer $TOKEN" \
  --data-binary "hello"

# 3) чтение
curl "http://localhost:8080/test.txt" -H "Authorization: Bearer $TOKEN"

# 4) удаление
curl -X DELETE "http://localhost:8080/api/delete?path=test.txt" \
  -H "Authorization: Bearer $TOKEN"
```

## Заключение

`config.json` — единственный источник конфигурации FileServer. Ключевые принципы:

1. **`users`** — учётные записи. Пароли в открытом виде, `console: true` — полноценный shell.
2. **`shares`** — виртуальные ресурсы. `name` (видит клиент) отделён от `physical` (путь на диске).
3. **`access`** — три независимых права: `read`, `write`, `delete`.
4. **`quota`** — две независимые квоты (пользователь и share); обе проверяются на каждой записи.
5. **`anonymous`** — открывает share всем; при `true` массив `users` игнорируется.
6. **Правки требуют перезапуска** — горячей перезагрузки нет.

При любых проблемах сначала проверьте:

- Валиден ли JSON (`json.tool` / `jq`).
- Совпадают ли `users` у пользователя и у share (регистр важен).
- Существует ли `physical` на диске.
- Не занят ли `port`.
- Нет ли дубликатов `name` в `users` или `shares`.


Тестовый `config.json` с комментариями всех трёх видов:

```jsonc
// Основной конфиг
// Комментарии вырезаются ДО парсинга

{
  /* Секция http */
  "http": {
    "port": 8080,          // основной порт
    "host": "0.0.0.0"      # слушать все интерфейсы
  },

  # Каталог статики
  "web": "www",

  "users": [
    // Админ
    { "name": "admin", "password": "admin123", "quota": -1, "console": true },

    /* Гость без пароля */
    { "name": "guest", "password": "",          "quota": 100, "console": false }
  ],

  "shares": [
    {
      "name": "Documents",
      "physical": "C:/data/docs",           // путь на Windows
      "access": ["read", "write", "delete"], // все права
      "anonymous": false,
      "users": ["admin"],
      "quota": 200
    },
    {
      "name": "Public",
      "physical": "D:/Public",              # путь на другом диске
      "access": ["read"],
      "anonymous": true
    }
  ]
}
```
